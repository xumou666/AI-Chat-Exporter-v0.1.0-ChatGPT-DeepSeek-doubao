fix(deepseek): 用真实页面结构修复切换对话混入其它对话 (v0.1.4)

依据：chat.deepseek.com 分享页的真实 DOM（结构与属性原样取回后分析）。
实测结构：
  .ds-virtual-list > .ds-virtual-list-items > .ds-virtual-list-visible-items
  每个渲染项带 data-virtual-list-item-key = 该对话内的消息序号（1,2,3...，游客横幅 -999）
  用户项外层哈希类 _9663006；助手项外层 _4f9bf79；助手正文语义类 ds-assistant-message-main-content

修复：
1. 按 item key 的连续性切分会话（关键）。混在一起的旧项与当前项通常在同一容器内，
   上一版只做"容器聚类"因此没生效；现在序号不连续即判定为多段对话，
   只保留当前那段（屏幕可见 > 消息更多 > 文档顺序靠后），并告警 dropped 数量。
2. 适配器改用实证结构判定角色（ds-assistant-message-main-content / _9663006 /
   _4f9bf79 / .ds-message），行选择器优先取虚拟列表项。
3. 负 key 的哨兵项（分享横幅、占位）不再当作消息。
4. isVisible 追加零尺寸盒子（height:0 + overflow:hidden 缓存面板）与祖先 opacity:0。

新增（诊断与兜底）：
- 「复制诊断」按钮：一键复制版本 / 页面 / 策略 / scopedBy / 候选与丢弃数量 /
  每行 key 与角色依据，直接贴进 issue 即可定位。
- 「点选范围」按钮：点当前对话第一条 + 最后一条即填入范围，不依赖启发式。
- 面板标题显示版本号；诊断列出 key、kept/dropped 与 scopedBy。

测试 69 -> 76：新增真实结构夹具（分享页 DOM，文案替换为合成内容）与
"切换对话后虚拟列表混入旧项"复现夹具，以及两个 UI 用例。
